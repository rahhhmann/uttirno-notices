## Bugs found and corrected
- Broken NodeNext declaration interop in the installed CommonJS robots parser was isolated behind a typed factory matching its actual installed API.
- An oversized response could emit end before the destroy error and become a false empty success. The transport now rejects synchronously, checks response completeness, and handles aborted streams; the real socket test passes.
- Malformed origin/seed strings cannot throw raw URL errors out of schema validation.
- Source changes and trust-key revocation are checked again before dispatch, not only at initial load.
- Expected link/attachment shapes fail visibly instead of silently producing complete discovery.

## Source state and material limits
No real source is activated or signed. Ownership/collection/display rights remain independently reviewable; unresolved collection rights cannot be assumed from official origin or robots. BPSC authority robots returned 404; no absence exception was approved. Alljobs is permission-pending. Oracle storage links are observations only and are not implicitly allowlisted.

A completed M2 discovery graph is not complete job extraction/publication. PDF text/OCR, semantic field verification, durable artifacts, canonical jobs and publication are M3/M4. Admin approval UX is M5/M6. Signatures prove reviewed-config integrity, not factual/legal correctness of a reviewer assertion.

Host limits are process-wide: operate one acquisition broker process until M4 distributed leases. Production OS/container egress and full resource isolation remain M8 work. Browser is offline and broker-fulfilled with sandboxing/limits, but those application controls do not replace the M8 deployment boundary. URL-changing browser redirects and nonstandard robots redirects fail closed.

The Linux CI definition includes Chromium/dependency installation. Local checks passed; the actual remote CI run is separate evidence in GitHub Actions and must be inspected rather than assumed.

The first Linux CI run exposed Ubuntu AppArmor user-namespace restrictions preventing sandboxed Chromium startup. The CI helper now installs exact-executable-path user-namespace profiles on ephemeral GitHub runners, following Chromium's documented selective approach. It refuses non-CI execution and does not globally disable AppArmor or turn off Chromium sandboxing. The updated remote run must prove the fix; the local Windows pass alone is insufficient evidence.
