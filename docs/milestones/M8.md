## Observed scope limits

Logical dump encryption is bounded to 64 MiB in memory; fixture keys are ephemeral. The restore fixture uses a tiny two-position synthetic corpus and verifies publication/evidence/audit plus original-byte hash. Its timing is not an agreed production RPO/RTO. HTTP load uses 100 requests, four concurrent clients and two synthetic positions; it does not establish realistic user/source scale or an SLO.

Native image uses the verified Node base digest and installed Debian Poppler/Tesseract ben+eng; actual engine/model fingerprints remain in text versions. Native package repositories may update, so final release image digests are authoritative. Container hardening is not a kernel/native exploit certification or real-corpus accuracy evaluation.

The application image contains no Chromium. Sources requiring browser-rendered acquisition need a separately provisioned, hardened and tested browser runtime before acceptance.

Portal/admin share the API's loopback network namespace in this integration definition; replace the API/web group together. The TLS template requires actual approved hosts/certificates and is not live-edge validation. External Uttirno main-site routing/assets/SSO/consumer sessions are untouched. Real staging retains production fail-closed config rules; the explicitly synthetic local rehearsal uses development API configuration, never a fake live provider.

Schema 0004 is additive but M7's strict schema reader expects 0003. App-only rollback to M7 against 0004 is unsupported. Container recreation is restart recovery, not previous-release rollback. Retain a truly compatible image or separately authorize a write-frozen DB/archive restore. Never hide the mismatch by deleting migration history or weakening readiness.

Expired stored content remains read/publication-gated; an aggregate retention review signal does not implement a legitimate destructive purge/legal-hold policy. Offsite durability/key rotation/retention owner and actual notifications remain external gates.
