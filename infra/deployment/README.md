# Deployment runtime

[Dockerfile](Dockerfile) builds the locked app and a separate Poppler/Tesseract parser from a verified Node base digest. [Compose](compose.yaml) sets non-root/read-only/no-capability/resource/secret-mount boundaries. Parser is network-disabled, receives bytes over Unix sockets and has neither database credentials nor an archive mount. API archive mount is read-only; only explicit worker acquisition has write access. No Docker daemon socket is mounted. No source activates on startup.

Build app/parser with the two Docker targets; use immutable registry image digests for actual rollout. Local tags are allowed only by the explicitly synthetic rehearsal. Runtime limits follow [Docker resource controls](https://docs.docker.com/engine/containers/resource_constraints/) and [Compose service controls](https://docs.docker.com/reference/compose-file/services/).

## Protected host configuration

Set RELEASE_IMAGE, PARSER_IMAGE, API_ENV_FILE, WORKER_ENV_FILE, MIGRATION_ENV_FILE, PORTAL_ENV_FILE, ADMIN_ENV_FILE, API_CONFIG_ROOT, WORKER_CONFIG_ROOT and the worker's existing ARCHIVE_ROOT outside Git. No default archive/config path is assumed. API/worker/migration need separate pre-created DB users; actual privileges are applied by the owner-operated database maintenance command. Environment files must be readable only by the deployment owner. No real passwords/identities are generated by these templates.

Production API/worker environment uses NODE_ENV=production, valid HTTPS S3, actual fixed external origins/OIDC/trust settings and OPERATIONS_TOKEN. Preflight requires verify-full PostgreSQL TLS and rediss, plus distinct DB identities. Public/staff Next processes receive only their respective web settings, never DB/OIDC client credentials. Only API/worker receive PARSER_SOCKET through Compose; parser receives none of their environment files.

The public/staff Next containers share the API network namespace to retain the existing loopback-only HTTP API-client contract. Recreate API/portal/admin **together** on replacement. Host ports are loopback 18400/18300/18301; no internet routing/TLS/domain is supplied by Compose. The [TLS proxy template](proxy.conf.template) requires actual approved hosts, certificates and host syntax/security review; it is not an already tested/live edge deployment. Set HTTP_TRUSTED_PROXIES only to exact real proxy IPs; proxy overwrites forwarded client IP and preserves the browser Origin. Never expose /internal. Reconfirm callback routing, Host cookies, Origin/CSRF and expiry on the actual staff domain.

## Explicit rollout

1. Resolve host/SSO/owner/volume decisions and validate protected config with npm run ops:preflight. Its result is configuration syntax, not live verification.
2. Record previous app/parser digests, schema compatibility, config references and an encrypted DB/archive backup whose restore is verified. Freeze writes where a restore may be required.
3. Run the explicit maintenance profile for migration; it never seeds. Apply grants separately with node packages/database/dist/maintenance.js grants API_ROLE WORKER_ROLE under the migration owner's private environment.
4. Start parser/API/portal/admin; wait for real readiness and run approved-only public/staff-denial smoke. Enable acquisition profile only after independent real source/operator/config gates.
5. Verify actual TLS/proxy/SSO/cookies, original-page display and cache/suppression behavior, then monitor. Do not open public traffic before release gates.

Schema 0004 is additive, but M7's strict readiness expects 0003. M7 is **not** a compatible app-only rollback after migration. Use a genuinely retained 0004-compatible release or a separately authorized write-frozen DB/archive restore. Recreating the same image group proves restart recovery, not an earlier-release rollback. No destructive down migration or automatic restore is performed.

## Development acceptance

npm run test:deployment is opt-in and requires the two local images tagged uttirno-m8:local / uttirno-m8-parser:local and the existing dedicated loopback services. It creates guarded synthetic schemas/users/private environment files, tests actual Compose readiness/native isolation/PDF processing/permissions/metrics and group recreation, then removes its own containers/temp files/roles/schema. Named volumes are retained; native PostgreSQL 5432 is untouched. Reports are ignored under .local. The independent CI rehearsal job builds and runs this without any real provider/site credential.

Real staging, approved real-source browser acceptance, live provider, owner delivery, compatible previous release and production load/restore/retention remain external gates. [M8 report](../../docs/milestones/M8.md), [ADR0012](../../docs/decisions/0012-m8-operations.md).
